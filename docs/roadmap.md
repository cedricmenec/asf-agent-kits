# Implementation milestones

## ACTIVE MVP DELIVERY ORDER (decision 24 October 2026)

**The R0–R7 bullets below are preserved *historical evidence*, not the MVP's critical path.** [Installation-first scope, explicit MVP acceptance and ASF V3 reuse decisions](mvp-installation-scope.md) and [living Notion roadmap](https://app.notion.com/p/40112ac91636818dab99de3813963c0c) supersede their ordering. Prioritize [#88 real portable ThreadStep OpenCode+OpenSpec kit](https://github.com/cedricmenec/asf-agent-kits/issues/88) → [#89 working install/status/doctor CLI](https://github.com/cedricmenec/asf-agent-kits/issues/89) → [#90 safe draft PR/setup](https://github.com/cedricmenec/asf-agent-kits/issues/90) → [#91 E2E on another approved repository and version upgrade](https://github.com/cedricmenec/asf-agent-kits/issues/91). Existing tools are previews, **not** an executable release. Preserve previous R3h/CAS/tests; do not extend them by default. Do not import local CAS into V3 unreviewed; reuse assessment is [ThreadStep #196](https://github.com/cedricmenec/threadstep/issues/196). Correct the current R2d confinement to `.asf/agentkit/` **explicitly and safely** before generating real `.github/workflows/` files. Admin, paid model, protected Git refs and release permissions remain gated.

This is a dependency plan, **not** proof of completed runtime implementation.

- **R0, scaffold**: project structure, provisional JSON schemas, ADR, kit descriptors and offline tests. This folder is the initial artifact.
- **R1, contract validation**: formal Draft 2020-12 validator + positive/negative fixtures; GitHub CI with pinned actionlint, tested at the exact PR SHA; no payments. (Integrated on main; SHA-exact CI green.)
- **R2, offline renderer/status (prototypes integrated)**: R2a status/dry-run, R2b three-way merge preview, R2c canonical candidate manifest, and R2d-01/02/03/04 deterministic template previews, manifest composition, target collision detection and explicit ownership/overlay rejection. All remain read-only, with no verified source provenance, atomic installer or runtime activation. See PR #25, #27, #29 and #31.
- **R3, OpenCode + OpenSpec kit (partial)**: R3a manual-policy, R3b GitHub proof preview, R3c GET-only adapter, R3d SHA host binding, R3e-01 host identity/permissions contract and R3e-02 simulated identity bootstrap are integrated (PR #23 and #33 for R3e). They **do not authenticate a real host** or authorize payments. Still to implement: real manual runtime phases, OPSX, strict checklist, durable checkpoints and a safe PR publisher without ASF V3 workflow_call. R3e-03 is an explicit host/installation qualification gate.
- **R3f, OpenSpec offline lifecycle (integrated mocks)**: R3f-01 to 04 simulate plan/apply/auto/finalize checkpoints, strict checklist, resume constraints, OPSX sync/--skip-specs archive guards and end-to-end mock composition. PR #37, #39, #41, #43. No authenticated runtime, LLM, semantic sync, PR publisher or paid retry.
- **R3g, disposable filesystem/Git qualification (integrated)**: R3g-01 to 05 verify actual temporary fixture bytes, strict local mock locks/overlays, Linux fd-relative O_NOFOLLOW inventories, local Git object/SHA parity and one integrated simulated OpenSpec recipe. PR #45, #47, #49, #51, #53; parent issue #44 closed. Even the integrated test does not prove remote GitHub refs or an atomic global filesystem snapshot.
- **R3h, manual runtime handoff / checkpoint journal (offline steps integrated)**: R3h-01 PR #69 composes R3a manual request and R3f synthetic OpenSpec phase/checkpoint constraints with SHA, scope and simulated paid-job concurrency matching. R3h-02 PR #77 adds versioned, digest-chained JSON journal entries and strict plan/apply/finalize manual recovery previews (issue #76 closed). R3h-03 PR #79 writes/reads these journal bytes exclusively within an owned disposable Linux temp directory and tests truncation, symlink, permissions and corruption (issue #78 closed). Both return denied authority and do **not** provide operational GitHub storage, authenticated remote refs, distributed CAS, a paid-job mutex or automatic paid retry. R3h-04a PR #84 additionally qualifies **only a disposable Linux filesystem CAS** with single mkdir-exclusive local lock, expected journal digest/version, fsync+rename, interrupted-write recovery and negative fixtures; R3h-04b PR #85 validates the local lock between two concurrently live processes and denies stealing a SIGKILL-orphaned lock. This does **not** establish GitHub CAS, an independently attested source, a global paid-job mutex or a real runtime. See `docs/r3h02-checkpoint-journal.md`, `docs/r3h03-disposable-byte-qualification.md`, `docs/r3h04-disposable-local-cas.md` and `docs/r3h04b-live-interprocess-lock.md`.
- **SEC-02 (partial, not activated)**: main branch protection SEC-01 is active; release claim validation SEC-02a #18 and synthetic release tag/permission/artefact-byte consistency SEC-02b-01 #55 are integrated. Parent issue #9 remains open: independently authenticated tag/release provenance, immutable tag rules, publisher identity and attestation are unproven. Never infer trust from matching synthetic booleans.
- **R4, optional OpenCode direct**: same policies and protected paths, shared per-repo paid-job concurrency, independent profile installation.
- **R5, PR installer/upgrade/rollback (partial, only previews integrated)**: R5a-01 PR #59 classifies local `unmanaged-legacy`/`drifted`/`unknown`, never `verified`; R5a-02 PR #61 previews strict stable SemVer transitions; R5a-03 PR #64 aligns managed files with R2d's `.asf/agentkit/` ownership boundary; R5b-01 PR #65 composes only an untrusted *in-memory* draft-PR envelope, not a GitHub branch, commit or PR. R5b-02a PR #71 validates only a synthetic target branch/SHA/CI/publisher observation, with all publication/authority grants false. Still ahead: independent source verification, safe controlled PR publication R5b-02, actual upgrade/rollback application with isolated host and conflict protections. No deployment authority, no direct settings writes.
- **R6, qualification (partial, local mock)**: R6a-01 PR #73 integrates local disposable target lock/file status, SemVer transition, non-writing draft PR plan and synthetic publication preflight, with negative scenarios and zero authority. Still ahead: isolated multi-repository qualification, real independently attested release candidates, upgrade/rollback in a separate test repository and SHA-exact CI there. No installation was performed. Publish first real SemVer release only after review.
