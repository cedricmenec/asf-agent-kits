# Style guide

Use this guide for every README, catalogue page, kit guide, diagram and illustration. Keep it simple. Help readers understand and act with as little effort as possible.

## Writing guide

### Write in simple global English

Write for readers who do not speak English as their first language. Use common words, short sentences and active verbs. Keep one main idea per paragraph. Avoid idioms, jargon, marketing claims and filler.

Use a technical term only when it helps the reader act or understand the tool. Explain an unfamiliar term on first use. For example: "A pull request (PR) is a proposed change that people can review before it is merged."

### Put the essential point first

Start each page, chapter and section with what the reader needs to know or do. Then add the steps, examples and details. Put optional technical depth later. Do not make readers search through history or design discussion to find an action.

Use short informative headings. Keep catalogue-wide content at the catalogue level. Put workflow-specific instructions inside that workflow's section.

### Explain difficult ideas intuitively

Add a brief mental model or concrete example when a concept is hard to grasp. Keep it close to the concept, and use only as much explanation as needed.

For example: "Think of a kit as a versioned recipe installed in your repository. It gives the agent a workflow to follow."

For a lock file: "The lock is an inventory: it records the installed version and file fingerprints so you can spot changes."

Use familiar comparisons carefully. A comparison should explain the idea without suggesting guarantees the software does not provide.

### Keep the text useful

State what the tool does, when it helps, what the reader must provide and what result to expect. Prefer a concrete example to an abstract explanation. Define limits where they affect a choice.

Avoid repeated explanations and long lists of concepts. Link to details instead of copying them across pages. Do not invent instructions for unavailable features.

### Punctuation

Never use an em dash or an en dash. Use a short hyphen (-) if a dash is needed. A full stop, comma, colon or separate sentence is often clearer.

Apply this rule to titles, headings, prose, tables, captions and new image labels. Keep executable code and exact external identifiers unchanged when editing them would change their meaning.

### Check before publishing

- Can a new reader understand the purpose in a few seconds?
- Is the next action clear?
- Are the words familiar to a non-native English reader?
- Are difficult ideas explained with a short useful model?
- Are the essential facts first and optional details later?
- Are there no long dashes, filler or unsupported claims?

## Visual guide

### Current direction: one humanity, one line style

Use subtle luminous pigment: the same ochre strokes hold the ancestral texture and a delicate ethereal light. No separate primitive and divine human populations, no evolutionary procession, no distinct divine figure. Flat 2D remains required. Variants A and B are the selected visual references.

### Main rule

Use flat 2D illustration. Make the main message clear in a few seconds.

Every illustration combines precise futuristic technology with one unified human mark-making style. Each human figure or gesture blends ancestral pigment and ethereal light inside the same strokes. Past and future coexist in the same humanity. This is a symbolic visual language, not a claim about what the software does.

### The visual story

**One humanity: luminous pigment, connected by digital paths.**

Every human mark expresses both our ancestral roots and an ethereal, almost divine possible future. Use rough ochre pigment containing fine ivory gaps and restrained pale-gold flecks within the same line. Circuits and data paths express AI and agent technology.

Use the same hybrid pigment-and-light style wherever humans appear. Do not split humanity into primitive people on one side and luminous beings on the other.

### 1. Roots: cave painting

Use recognizable ochre hand stencils, rough pigment strokes, simple painted human figures or a restrained animal outline. Their scale may be small, but they must be recognizable. Color alone or stone texture is not enough.

Avoid stereotypical cavemen, decorative ethnic clothing and culturally specific sacred symbols.

### 2. Technology: precise digital paths

Use crisp teal circuit traces, data nodes, code signs and clear system boundaries. Show useful flows, not decorative complexity. Keep technical relationships accurate.

### 3. Becoming: ethereal human light

Express the ethereal through delicate open contours, fine ivory interruptions and sparse pale-gold marks embedded in the same cave-painted figure or gesture. Avoid a separate elevated figure, halo or divine zone.

Draw light as flat ivory gaps and pale-gold flecks inside pigment strokes. Keep it subtle and inseparable from the ancestral line. Avoid monumental rays, separate halos, photorealistic glow, 3D shading and gradients.

The divine quality should feel universal and poetic. A specific religious identity, deity or sacred symbol is not required.

### Flat 2D is the preferred style

- Flat opaque fills and clean readable outlines.
- No perspective rendering, sculpted stone blocks, realistic hands or 3D objects.
- Rough pigment edges belong only to ancestral marks.
- Ethereal light remains a flat graphic shape.
- Plenty of empty space around text and the main flow.
- Short labels in simple English.

Use gold sparingly. Keep text in charcoal on a light field. Meaning must remain clear without color.

### Composition

Connect luminous-pigment human gestures with crisp circuit paths. Each human motif already combines ancestral and ethereal qualities; it should not transform into a separate type of being.

Avoid three unrelated decorative zones. The roots, technology and light should feel like parts of the same human story.

The product message stays in the foreground. The symbolic journey must not imply guaranteed correctness, automatic merging, spiritual effects or capabilities the software does not provide.

### Diagrams and architecture

Use the same unified human style at a smaller scale: a single luminous-pigment gesture beside precise technical lines. The same stroke must carry both ancestral texture and ethereal light. Keep it away from labels and system boundaries.

Use 4-6 main nodes where possible, clear arrow meanings and one main message per view. Keep human decisions, credentials, providers and trust boundaries explicit.

For Mermaid, use the same warm human-node style for input and review, with teal system nodes. Do not assign primitive and divine identities to different nodes. When freeform illustration is limited, favor the clearest functional model. Keep an accessible text description.

### Reusable art direction

Create a clear flat 2D illustration for ASF Agent Kits. Connect precise futuristic teal circuits with a single human visual language: delicate rough ochre pigment strokes containing sparse ivory gaps and pale-gold flecks. In each human figure or gesture, ancestral roots and ethereal, almost divine becoming coexist within the same marks. No separate divine figure or primitive-to-divine procession. Use few elements, generous empty space, simple English and an intuitive functional flow. Avoid 3D, realistic hands, cinematic glow, halos, religious specificity and decorative clutter. Preserve all functional meanings and technical boundaries. Keep it simple; reduce mental and cognitive load.

### Before delivery

Check that the main message is clear at thumbnail size. All three layers must be present and connected, with readable labels and accurate technical meaning. The human light must remain a symbolic accent. Keep the editable diagram source or generation prompt with the final image.
